# 0.9.0 alpha — clean packed 4K native project saving

Qualified alpha packages and retained evidence are identified below.
Windows qualification remains deferred.

The bounded native-save profile now admits an already-loaded clean packed FILE
image at 4096 × 4096, while retaining an existing empty Sequencer and its default
channels. The qualified large fixture uses one image: all 67,108,864 RGBA Float32
components, packed bytes, color role and declared image/material/UV bindings are
compared through genuine queued saves and fresh product reader processes.
Matching add-on, MCP wheel and plugin versions are 0.9.0, with 270 public tools.

The limits remain finite: 16,777,216 aggregate image pixels, 80 MiB packed data
and a 256 MiB native-file ceiling, within the existing one-Scene/declared-data
profile. Dirty or GENERATED images, edited CURRENT_PIXELS portability, a paired
4K original/helper workflow, authored Sequencer content and arbitrary production
projects are not qualified. This increment does not close ordinary startup,
material, recovery, H01 or full artist-workflow requirements.

`project.native_save_preview` and `project.native_save_start` require an approved
project folder, Inspect Scene, Save Project, Access External Files, and the
separate expiring **Native Save Effects** grant. That grant starts off and is
armed locally in Blender; MCP cannot arm it. Native Save/Save As can synchronize
state and run callbacks or other native effects outside the selected folder.
A native call cannot be preempted. Failed, revoked or canceled jobs can retain
files and effects and do not promise rollback. Copy New creates an unused final
path after staged verification; Save Current/As retain their disclosed native
destination race. The legacy `project.save` remains held.
