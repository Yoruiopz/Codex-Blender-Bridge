# Blender Codex Bridge 0.9.1 — alpha

This is a narrowly scoped reliability candidate. Publication requires the exact
candidate packages to pass the checks below; a version number or a successful
source-only test run is not release acceptance. The accepted release page will
identify the final commit, CI run, package checksums and retained evidence.

## Release scope

The release retains the **270 public MCP tools** from 0.9.0. Five unqualified
GLB staging candidates are excluded from both normal Blender registration and
MCP discovery/dispatch. Their implementation and explicit development tests
remain preserved for the longer-term workflow.

Runtime changes strengthen cancellation and revocation before lifecycle
invalidation, canonical executor/job-context checks and optional-context
compatibility. Permissions remain authoritative inside Blender. Transport stays
on literal `127.0.0.1`, mutations stay on the main thread, and arbitrary Python
remains off by default.

The required installed acceptance scenario uses one owned, untextured static
Cube in a clean disposable project:

1. Create and transform it through the installed MCP wheel and installed add-on.
2. Independently inspect its geometry and authored transform.
3. Run an isolated geometry preview and retrieve its PNG.
4. With locally configured project-folder permissions and Native Save Effects
   consent, save a new `.blend` through the existing bounded native-save job.
5. Verify the same asset through the product's fresh reader and compare retained
   parent identities, geometry and transform.

The external client cannot grant local consent. Geometry previews certify the
declared untextured shape only; they do not certify original materials, lighting
or a protected viewport capture. Factory cleanup is explicit owned fixture
setup, not proof of arbitrary existing-project admission.

## Qualification required before publication

Build the add-on ZIP, MCP wheel, plugin ZIP and checksums from one clean,
version-matched commit. Require all seven same-commit CI jobs, including the
Python 3.10–3.12 × MCP SDK 2.0.0/2.2.0 matrix. Audit package members, wheel
RECORD, component versions and checksums.

Replay applicable native regressions on official Linux Blender **4.5.14**
(`62c1db4208e8`) and **5.2.2** (`d13f752e3b9c`). Verify exact downloaded
candidate packages through fresh installation, previous-0.9.0 replacement,
upgrade/rollback, paths containing spaces, listener restart/reconnect and the
same-asset scenario above. Retain reviewed preview images and report the actual
tested SDK/build combinations. Component denial/interruption checks remain
separate from any untested end-to-end failure scenario.

Use a new fixed alpha publisher with exact artifact and evidence pins. Verify
downloaded published bytes against accepted hashes. Preserve previous releases,
main, draft PR #8 and repository visibility.

## Limits and deferred work

This is not stable 1.0. Windows compatibility and testing remain **deferred and
unverified**. The complete [artist-workflow checklist](../implementation-completion.md)
and all fourteen stable release gates remain open; the broader target is
preserved for later work.

The release adds no new modeling, texture, animation, simulation, GLB/FBX or 4K
capability claim. Existing finite native-save limits remain documented separately
in [the save contract](../native-project-saving.md); historical 0.9.0 evidence is
tied to its own bytes. Ordinary production projects, edited/generated textures,
durable paired recovery, original-material protected capture and complete
delivery scenarios remain unqualified.

Legacy `project.save`, protected capture, shader REMOVE/conversion, the held
Timeline/provider work and exact-build import quarantine retain their existing
restrictions. The new private root-approval helper, bulk metadata diagnostic,
unfinished cold fixture and inspection deadline work are excluded from this
release increment's acceptance claims. No unsupported project should be cleared
or downsized to force admission.
