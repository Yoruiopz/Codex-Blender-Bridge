# Blender Codex Bridge 0.7.0 — alpha candidate

**Candidate source, not a published release.** Add-on, standalone MCP server and
optional plugin metadata match **0.7.0** with the Alpha classifier. The public
registry remains **268 typed MCP tools**; two internal tools remain hidden.
Use the [published 0.6.0 alpha](0.6.0.md) and its matching verified installers
until a 0.7.0 candidate is accepted and published. The installation guide and
recommended download remain on 0.6.0.

This candidate prepares retained direct-weight recovery, bounded raw F-curve
point editing and populated selected-field protection evidence for isolated
geometry previews. It does not complete the full artist workflow. All
[29 implementation items](../implementation-completion.md) and
[14 stable-release requirements](../release-1.0-readiness.md) remain **OPEN**.
Windows compatibility and testing remain deferred and unverified. Only official,
unmodified Blender is targeted; no fork or custom build is required.

## Candidate changes

`weights.assign` and `weights.normalize` retain one original factory, immutable
Float32 intent and complete admitted preservation projection. Live authority and
full expected-prefix comparison precede each native membership call. Recovery
may reverse only verified attempted fields under current authority. Permission
loss, foreign edits or unknown state stop later writes and prevent an unproved
inverse. The ordinary profile is local, editable, single-user, populated Mesh
storage in Object Mode, with explicit consumer/runtime/dependency caps. Unsupported
profiles refuse; other weight tools are not newly qualified. Read the
[direct-weight contract](../weight-edit-safety.md) before using it.

The source-specific weight recovery fixture has selected prepared-context native
evidence on both pinned Linux builds. It uses an explicit genuine setup checkpoint
before original intent capture; cold-context expanded preservation remains
unqualified. Verified rollback is not native undo, durable recovery, mixed manual
undo, cancellation/disconnect, character deformation or constrained-memory proof.

`animation.curve_edit` admits **`RAW_FREE_POINT_V1`**: exact raw `co`, `handle_left`
and `handle_right` Float2 assignments on existing keys whose handles are already
FREE. The additive optional `co` field changes a value while preserving the
selected key's Float32 frame bits. The selected current key/pose must remain
unchanged. Canonical native setters receive a separately predicted complete
Action prefix; no `FCurve.update`, sorting, `co_ui` setter, key recreation or
baseline adoption occurs. Attempted-field recovery uses the same live-authority
and complete-prefix rules. This writer's final integrated native qualification
is still pending; source/model checks alone do not qualify a registered write.
See the [exact curve profile](../animation-curves.md#edit-existing-raw-point-fields).

The separate `geometry_preview_populated_protection` source case creates a real
nonempty protected Mesh, actual material binding and stored Action keys. It calls
real plan set/capture/enforce before pending raw-state setup, captures
`mesh_geometry`, `material_slots` and `animation`, and seals the actual baseline
metadata and cached record. Real start/poll/image and comparison calls, three
delayed turns, manual vertex/key changes and actual evidence eviction check the
selected data independently. Complete comparisons must be truthful; manual edits
remain intact and evicted evidence stays unknown while enforcement remains active.
The original null-baseline control remains. No new runtime protection profile,
permission or production API is introduced by this acceptance case.

Raw diagnostics are retained around each API and delayed turn. Immediate raw
equality is required only where the existing geometry start/image contract claims
it. Generic inspection/comparison and idle UI turns have no universal raw-purity
claim. Pending evaluated pose/raw visibility are outside this selected-data case.
Identity/consumer enforcement and advisory evidence remain distinct; neither
certifies full protected objects or hidden Main state. See
[geometry preview limits](../geometry-preview.md) and [plan semantics](../task-plans.md).

## Compatibility and migration

The protocol envelope, existing tool names, literal loopback transport,
main-thread execution and Blender-authoritative permissions are unchanged.
The declared Blender 4.2 minimum and standalone Python 3.10+ remain unchanged;
those declarations do not qualify every platform or Blender build. The new
ordinary writer profiles admit only the exact reviewed official Linux Blender
**4.5.14** (`62c1db4208e8`) and **5.2.2** (`d13f752e3b9c`) builds within their
individual context restrictions.

For curve editing, valid interpolation/easing, handle-type and extrapolation
requests remain in the schema for compatibility but return `NOT_IMPLEMENTED` in
the first raw-point profile. Malformed enum values remain `INVALID_ARGUMENT`.
Both handles must already be FREE: requesting conversion to FREE is unsupported.
Current-frame value/pose revisions, key-time moves, non-FREE handles, broad rigs,
control/custom-property curves and broader curve/Action/NLA authoring need
separate supported contracts. Inspect the exact curve first and revise only
admitted stored fields. **There is no arbitrary-Python fallback.** Python remains
disabled by default and does not satisfy missing structured workflows.
