# Blender Codex Bridge 0.3.0 — faster structured scene work

108 MCP tools, including 20 additions for more precise, lower-round-trip Blender editing.
This remains **alpha software**: use backups and verify edits before saving important work.

## Download and install

Download the assets attached to this release, not GitHub's automatic source archives:

| Asset | Install |
| --- | --- |
| `blender_codex_bridge-0.3.0.zip` | Blender → Edit → Preferences → Add-ons → Install from Disk; select the ZIP without extracting |
| `blender_codex_bridge-0.3.0-py3-none-any.whl` | In your standalone Python 3.10+ environment: `python -m pip install ./blender_codex_bridge-0.3.0-py3-none-any.whl` |
| `blender-codex-bridge-plugin-0.3.0.zip` | Optional Codex plugin with MCP configuration and Blender Studio guidance; requires the installed MCP command on the client's PATH |
| `SHA256SUMS.txt` | SHA-256 checksums for the three packages |

Blender 4.2+ is the declared minimum. Real-Blender tests use 4.5.1 LTS and 5.1.2.
Pip needs internet to install dependencies. No source build is required.

Enable the add-on, open **N → Codex Bridge**, review permissions, and start the listener.
Register the MCP executable with
`codex mcp add blender_codex_bridge -- "<absolute path to blender-codex-mcp executable>"`.
Use manual registration **or** plugin registration, not both. Restart Codex/start a new
task and begin by asking for bridge status and scene inspection without edits.

See the [complete installation guide](https://github.com/Yoruiopz/Codex-Blender-Bridge/blob/v0.3.0/README.md#install--no-source-build-needed).
The repository remains private; downloads require repository access.

## New capabilities

- **Batching (2 tools):** preflight and execute 1–32 ordered structured steps, bounded results,
  per-step permission checks/history, cooperative cancellation between steps, explicit partial-failure evidence.
- **Interaction (4 tools):** explicit object selection/active object, supported mode transitions,
  paginated mesh-component inspection and indexed vertex/edge/face selection with stale-context checks.
- **Layout (4 tools):** filtered scene queries, up to 128 object transforms, world-origin alignment
  and distribution with measured post-state and conservative dependency checks.
- **Geometry Nodes (10 tools):** create/inspect node trees, add interface sockets and reviewed nodes,
  set properties/defaults, edit links, remove nodes, and attach graphs as modifiers.
- **MCP compatibility:** structured success and error envelopes work with SDK 2.0.0 and 2.2.0;
  actionable permission and disabled-tool errors remain visible without exposing internal tracebacks.
- **Release reliability:** matching component versions, wheel metadata/runtime checks, deterministic
  ZIP packaging, checksums, generated README inventory, and installable CI development artifacts.

All prior modeling, materials/shader nodes, UV, modifier, constraint, rigging, animation,
scene, camera/light/world, render, inspection, status/history, checkpoint and save tools remain.
The [README](https://github.com/Yoruiopz/Codex-Blender-Bridge/blob/v0.3.0/README.md#features)
lists every tool and the [workflow guide](https://github.com/Yoruiopz/Codex-Blender-Bridge/blob/v0.3.0/docs/agent-workflows.md)
explains limits and examples.

## Upgrade from 0.2.0 (or 0.1.0)

1. Save/back up your work normally. Stop the bridge and finish active tool calls.
2. Replace the old Blender add-on with the 0.3.0 ZIP and restart Blender to unload old modules.
3. In the **same environment registered with Codex**, run:
   `python -m pip install --upgrade ./blender_codex_bridge-0.3.0-py3-none-any.whl`.
4. Remove the historical `mcp==2.0.0` constraint from your installation instructions/requirements;
   0.3.0 no longer needs it. An already-installed SDK 2.0.0 remains compatible.
5. Update the optional plugin if used. Restart Codex/start a new task and start the bridge.
6. Verify add-on version with `bridge.status` and MCP version with
   `python -m pip show blender-codex-bridge` in the registered environment; both should be 0.3.0.
7. Review permissions, enable only required toolsets, and begin with inspection.

Do not mix add-on/server versions. No `.blend` migration is required, and installation
does not intentionally modify your scene. Selection IDs and undo checkpoints are session-local.
Rollback requires reinstalling both older packages; software downgrade does not undo scene edits.

## Safety and known limits

- Literal `127.0.0.1` only; never tunnel the listener. Blender checks permissions on its main thread.
- Batch planning is not a scene simulation or complete handler-argument validation. Earlier successful
  edits remain after a later failure; there is no automatic atomic rollback. Inspect before retrying.
- Long Blender operations cannot be interrupted mid-call; stop/cancellation takes effect at safe points.
- Layout uses origins, not surface spacing, and rejects dependent objects rather than guessing.
- Geometry Nodes is an allowlisted subset, not all nodes/zones/bakes. Shared graph edits need acknowledgement.
- Sculpt/paint mode entry is not brush automation; compositor, advanced NLA/driver/weight workflows,
  simulation/bakes and other specialist workflows remain outside the structured surface.
- Python stays disabled by default. It requires Python, delete, external-file and save permissions
  together and is **not a sandbox**. Do not enable it merely to bypass a structured permission denial.
- Checkpoints are global undo markers, not durable backups. Scene summaries/images go to the AI client;
  local transport does not imply local-only model processing.

## Verification

Release gates include the full non-Blender suite, lint and type checks; Python 3.10/3.11/3.12
with MCP SDK 2.0.0/2.2.0 in CI; clean wheel installation; and isolated factory-startup Blender
checks for baseline tools, interaction, layout, Geometry Nodes, and batching on 4.5.1 and 5.1.2.
These tests use temporary scenes, not the user's open project. They do not establish that every
Blender version, editor or production workflow is supported.
