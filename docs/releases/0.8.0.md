## Native project saving with a local session grant

`project.native_save_preview` and `project.native_save_start` add a typed path
for Save Copy, Save Current and Save As on standard, unmodified Blender. A local
expiring **Native Save Effects** grant is off by default and must be armed in
Blender, in addition to Inspect Scene, Save Project and Access External Files.
The MCP client cannot arm the grant or change the approved project folder.

Preview freezes source, destination, overwrite and loss facts. It is a modifying
intent-retention operation, not a passive inspection or a completed save. Start
requires the identical current preview and confirmations, accepts a bounded job,
and leaves completion to job inspection. Keep the owner connection open until
the job reaches a terminal state.

Native-save requests retain the canonical initial parameter-dependency hook and
queued admission boundary. Acceptance must exercise that hook through the genuine
installed Runtime/TCP queue, not through a permissive substitute. Existing authority,
source checks and protected-scope refusal remain in force.

- **Copy New** uses verified owned staging and create-if-absent final publication.
- **Save Current / Save As** disclose normal native overwrite behavior. They are
  not atomic destination compare-and-swap; explicit acceptance of
  `NATIVE_DESTINATION_RACE_NOT_EXCLUDED` remains required.
- Normal native saving can synchronize/flush state and invoke callback/catalog,
  history and other effects outside the project folder. The distinct local grant
  authorizes these effects; the bridge does not claim universal path containment,
  hidden-state equality or hostile-script isolation.
- Native calls cannot be preempted. Cancellation, disconnect, deadline or revoked
  authority prevents subsequent authorized work, but cannot undo an already
  completed save. Inspect known/staged/native files and uncertain effects on every
  failed or canceled result. Do not infer rollback from the terminal job state.

The first profile is deliberately finite: one local Scene, up to 32 Objects,
32,768 mesh vertices/131,072 corners, 64 bones, 64 curves/2,048 keys and supported
local material forms. At most four already-loaded, clean, packed FILE images
share a 1,048,576-pixel/20 MiB packed-data budget; hashed/reopened files are capped
at 256 MiB. Dirty/generated/4K image delivery and unsupported dependencies refuse.
Read the complete [native-save contract](../native-project-saving.md), including
all ownership, schema and resource limits, before using this alpha.

Factory palettes, line styles, transient Viewer/runtime images and sequencer/cache
state are not generally qualified by a cleaned owned fixture. The bridge must
refuse unsupported project data; users should not delete artist data to force
admission. Broader ordinary-project usability remains required development work.

## Compatibility and held features

The legacy `project.save` tool remains quarantined. Protected `viewport.capture`,
shader REMOVE/conversion, the held Timeline/provider reproduction and existing
exact-build import restrictions remain unchanged. No arbitrary-Python fallback is
used to fill these gaps; Python stays disabled by default.

Protocol envelopes, main-thread mutations, literal loopback transport and
Blender-authoritative permissions remain compatible. The declared Blender 4.2
minimum and standalone Python 3.10+ remain unchanged; those declarations are not
universal platform/build qualification. This new native-save profile targets the
exact reviewed official Linux **4.5.14** (`62c1db4208e8`) and **5.2.2**
(`d13f752e3b9c`) builds within its documented restrictions. **Windows compatibility
and testing are deferred and unverified.**

## Qualification requirements and release evidence

Every accepted 0.8.0 build requires retained evidence tied to its exact files:

- A clean reviewed source/commit and matching source/package fingerprints; all
  six component versions agree, without using their version strings as identities.
- All seven exact-commit CI jobs, including the six Python 3.10–3.12 × MCP SDK
  2.0.0/2.2.0 cells, configured static checks and documented tool inventory.
- Matching add-on ZIP, MCP wheel, plugin ZIP and checksums, with archive/member,
  immutable source, wheel RECORD and downloaded-byte validation.
- All registered save/reopen/authority/interruption scenarios on both exact
  official Blender builds, plus real installed queued preview/start/poll. Use
  genuine local grants/services and a persistent owner connection; no service or
  classifier substitution, fake permission provider or checkout product imports.
- Affected artist/image/Scene/job/undo/history regressions, fresh installed wheel
  stdio/schema behavior and the install/upgrade/rollback/restart/path-space routes
  actually claimed by the release. Separate wheel and Blender TCP checks do not
  establish a combined end-to-end path unless that path is exercised.
- Sanitized durable reports/logs, source/package hashes, reviewed visuals where
  needed, measured native blocking/memory/deadline behavior, and a current blocker
  plan. Retain failures and unknown effects; do not promote historical RAM-only
  reports or unrelated donor results into final acceptance.
- A reviewed fixed prerelease publisher that uses accepted bytes, preserves prior
  releases and verifies anonymous downloads. A source tag alone is not that proof.

The [0.8.0 release evidence](https://github.com/Yoruiopz/Codex-Blender-Bridge/releases/tag/v0.8.0)
is the authority for final accepted commit identities, package/evidence hashes,
measured outcomes and publication/download verification. The separate record keeps
these exact identities, measurements and download verification together. Earlier
fa81 development packages and published 0.7 files remain distinct and cannot be
relabelled as 0.8 evidence. Qualification is established by the evidence record for
the accepted artifact set; development branches remain candidates until reviewed.

## Required work still open

**All 29 implementation items and all fourteen stable-release gates remain
OPEN.** Broader save profiles, current edited-pixel packing and durable recovery,
4K production delivery, material/consumer recovery, full protected verification,
modeling/paint/character/procedural/cinematic workflows and complete installed
scenarios A–F remain required. The [0.8 blocker plan](0.8.0-blocker-plan.md)
records concrete next implementation and validation steps.

This is an alpha milestone, not stable 1.0 or complete portable `.blend`/GLB/FBX
delivery. Earlier releases stay available. Preparing or publishing this alpha
does not merge main or draft PR #8, change repository visibility, or resume
deferred Windows work.
