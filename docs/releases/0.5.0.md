# Blender Codex Bridge 0.5.0 — bounded 4K painting and guarded UV edits

**Alpha source candidate; not a publication announcement.** This checkout prepares
matching numeric 0.5.0 components with 266 public MCP tools. Bounded 4K painting
and direct UV guards are implemented; final combined-source, native and matching
installed-package qualification remains pending. Use disposable scenes and retain
normal backups. This source does not establish a published 0.5.0 release.

## Implemented candidate changes

- **4K source and stencil admission for surface-paint jobs.** The existing
  `image.paint_surface_job_start` admits up to 16,777,216 pixels in each input,
  with at most 4,096 pixels per axis. Synchronous
  `image.paint_surface_version` retains its 1,048,576-pixel limit. Geometry,
  orthographic projection, raw stencil roles and explicit consumer/permission
  contracts remain bounded. See [surface painting](../image-surface-paint.md).
- **Bounded raster memory.** Surface jobs use 64×64 ownership tiles, at most
  16 KiB of integer ownership scratch, and original-source Float32 comparisons
  without a complete normalized baseline. Every relevant selected triangle
  still participates in shared-UV-boundary checks, including outside the brush
  footprint. Complete source, stencil and output hashes remain required.
- **Finite work and visible job lifecycle.** Job counters are each capped at
  33,554,432 candidate-pixel, visibility-triangle and stroke-segment tests. The
  existing deadline remains 1–300 seconds; jobs may refuse after acceptance
  when work exceeds a cap. Progress, pause and safe-point cancellation use the
  existing single-owner job controller. No new job API or request schema is
  introduced, and no realtime or guaranteed-completion promise is made.
- **4K generated-image sculpt masks.** `mesh.sculpt_mask_sample` admits local,
  loaded, unanimated GENERATED RGBA images up to 4,096². Selected raw channels
  are copied through bounded chunks and validated completely, with independent
  final image/mesh/UV/context comparison and exact read-only lifecycle gates.
  Bilinear UV sampling and explicit MIN/MAX/MEAN seam reduction remain unchanged.
  See [sculpt-mask sampling](../surface-brushes.md).
- **Guarded direct UV edits.** Existing `uv.coordinates_set`, `uv.transform` and
  `uv.pin` retain independent intent before providers/checkpointing, compare exact
  Float32 bits including signed zero, resolve fresh native leaves and journal only
  attempted owned fields. Live authority and expected-prefix comparisons gate
  forward and restoring writes. Unknown outcomes, drift and authority loss latch
  further writes off. The initial profile is static, material-free, single-user
  Edit Mode with supplied physical buffers, UV sync disabled, at most 512 corners
  and eight maps subject to joint comparison limits. Calls are standalone; batch
  composition and artist-protected-plan operation remain unsupported. See the
  [complete UV profile and omissions](../uv-edit-safety.md).

Sculpt-mask sampling remains a **synchronous read**: it has no job ID,
asynchronous progress or `jobs.cancel` support. Cancellation/disconnect/deadline
flags are checked at safe points. Native pixel capture, allocation, full hashing,
image publication, readback and native checkpoint operations may block until
their current call returns. Late job failure can retain an image; inspect actual
effects and recovery facts instead of assuming cancellation means rollback.

At equal 4K source/stencil sizes, surface private kernel arrays are about 576 MiB
plus scratch; conservative publication/readback arrays are about 1,088 MiB plus
scratch. Sculpt sampling retains roughly 320 MiB of RGBA/channel arrays plus
bounded scratch. Native/GPU/undo/file buffers, geometry/plan objects and allocator
overhead are additional. These are source-level estimates, not measured process
peaks, constrained-memory acceptance or out-of-core behavior.

## Qualification and retained restrictions

Final reconstructed combined-source qualification still needs direct 4K native evidence: complete pixel
hashes, scoped sculpt results, full input preservation, completion within the
existing deadline, peak process memory, cancellation behavior and reviewed
appearance. Small analytic tests, policy-only dimension admission and source
review do not supply that evidence. Final exact-source CI, matching package
hashes and a new installed MCP session must also agree before publication.
No future commit, test count or successful native run is claimed here.

The direct UV guard is included in this candidate. Its final native qualification
must retain actual registered-tool success, denial, context, complete-map
preservation, injected-failure and measured recovery cases. Local dispatch cannot
prove real transport, native undo or durable recovery. Hidden AUTO texture-space
cache, internal temporary BMesh PYPTR allocation purity and persistent UV-layer
identity remain explicitly unverified. The guard does not complete F02 or REC-01.

Curve-writer, cloth-job and material-recovery increments under separate review are
not included. No operational cloth-job or cache-freshness claim follows from
portable models or source review. The historical modifying-tool audit remains
source-specific; no complete current mutator audit or A–F acceptance is claimed.

The [0.4.0 artist-workflow foundations](0.4.0.md) retain their domain limits.
In particular:

- `project.save` remains unavailable for Save and Save As; see
  [save safety](../project-save-safety.md).
- Protected viewport capture and shader-interface REMOVE/conversion remain
  unsupported; see [capture](../protected-capture-design.md) and
  [shader-interface limits](../shader-interface-lifecycle.md).
- Typed import remains quarantined on the known Blender 5.2.2 source build
  `d13f752e3b9c`; see [import containment](../asset-import.md).
- Windows-specific compatibility work and testing remain deferred. No Windows
  support verdict, complete artist workflow or installed A–F acceptance follows
  from these source changes. All fourteen [1.0 requirements](../release-1.0-readiness.md)
  remain open. The full [29-item implementation checklist](../implementation-completion.md)
  remains mandatory; PAINT/A05 and production sculpting are not declared complete.

The alpha classifier, protocol **1.0**, declared Blender **4.2.0** minimum and
standalone Python **3.10+** requirement remain unchanged. The manifest minimum
does not qualify every Blender patch or platform. Arbitrary Python stays
disabled by default; keep transport on literal `127.0.0.1`.
