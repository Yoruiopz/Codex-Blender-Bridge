# Blender Codex Bridge 0.2.0 — platform alpha

The first broad Blender editing release: 88 MCP tools for objects, meshes,
materials and shader nodes, UVs, modifiers, constraints, rigging, animation,
cameras, lights, world settings, rendering, and scene inspection.

This is an alpha: use copies or versioned backups for important projects.
It does not provide dedicated tools for every Blender feature. Python is an
optional, dangerous fallback, disabled by default—not required for normal use.

## Downloads

- `blender_codex_bridge-0.2.0.zip`: install this ZIP in **Blender → Edit → Preferences → Add-ons → Install from Disk**. Do not extract it first.
- `blender_codex_bridge-0.2.0-py3-none-any.whl`: install the standalone MCP server with `python -m pip install ./blender_codex_bridge-0.2.0-py3-none-any.whl "mcp==2.0.0"` in a Python 3.10+ virtual environment. Pip also installs dependencies; an internet connection is required.
- `blender-codex-bridge-plugin-0.2.0.zip`: optional Codex plugin package with MCP configuration and the Blender Studio workflow skill. Requires the installed MCP executable on Codex's PATH. Manual MCP registration works without this package.
- `SHA256SUMS.txt`: SHA-256 hashes for all three packages.

No source build is needed. Blender 4.2+ is the declared baseline; development
smoke checks have used Blender 4.5.1 and 5.1.2. Not every supported version or
specialist workflow has been tested.

**Compatibility note (2026-09-22):** use MCP SDK **2.0.0** with this historical
release. SDK 2.2.0 masks structured bridge exceptions, making permission/disabled-tool
errors less actionable. If already installed, run `python -m pip install "mcp==2.0.0"`
in the registered MCP environment and restart Codex. The 0.3.0 development adapter
fixes this and has tests for both SDK versions. These 0.2.0 assets remain unchanged.

## Connect

1. Enable the Blender add-on. In a 3D Viewport press **N → Codex Bridge**.
2. Review permissions and click **Start Bridge**. Keep `127.0.0.1:9876`.
3. Register the installed executable with Codex: `codex mcp add blender_codex_bridge -- "<absolute path to blender-codex-mcp executable>"`.
4. Start a new Codex task and ask it to inspect the scene without changing anything.

The bridge runs locally. Codex sends structured commands; Blender checks permissions
and executes them on its main thread. The panel shows connection, task, toolsets,
permissions, history, pause, emergency stop, and recovery controls. Checkpoints are
session undo markers, not saved backups. Keep the listener private and never tunnel it.

## Upgrade from 0.1.0

1. Save your work normally and keep a backup. Stop the bridge and close active Codex Blender tasks.
2. Disable/remove the older add-on, install the new ZIP, and restart Blender to unload old Python modules.
3. In the **same MCP virtual environment** run `python -m pip install --upgrade ./blender_codex_bridge-0.2.0-py3-none-any.whl "mcp==2.0.0"`.
4. If using the optional plugin, update that package too. Use either plugin registration or manual MCP registration, not both.
5. Restart Codex/start a new task. Start the Blender listener, review permissions, and ask for `bridge.status`.
6. Confirm add-on/MCP versions are 0.2.0 and start with inspection. Re-enable needed optional toolsets; old selection IDs and undo checkpoints are not portable across restarts.
