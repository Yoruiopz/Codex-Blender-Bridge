# Blender Codex Bridge 0.4.0 — bounded artist workflows

**Alpha prerelease candidate.** This source prepares matching 0.4.0 components and
contains 266 MCP tools. It does not yet establish acceptance or publication of the
packaged candidate. Use disposable scenes or project copies and retain backups.

The [0.3.0 release](https://github.com/Yoruiopz/Codex-Blender-Bridge/releases/tag/v0.3.0)
and earlier releases remain available unchanged. **1.0 is not ready:** all fourteen
[release requirements](../release-1.0-readiness.md) remain open.

## Changes since 0.3.0

- **Artist interaction:** bounded plans, exact runtime references, transform
  preview/apply, explicit protected scope and step-linked execution receipts.
  `task.plan.verify_transform` compares independently retained intended core
  transform channels, including Float32 bits and signed zero. Sidebar target
  records are historical; neither a recorded match nor a marked step verifies
  the user's artistic goal. See [task plans](../task-plans.md) and
  [target verification](../artist-target-verification.md).
- **Modeling, UVs and painting:** bounded repair/refinement, explicit sculpt
  PUSH/SMOOTH strokes, painted-image mask sampling, color-attribute lifecycle,
  vertex-color brushes and surface texture/stencil workflows. Each operation has
  explicit geometry, ownership and preservation limits. See
  [mesh repair](../mesh-repair.md), [UV authoring](../uv-authoring.md),
  [sculpt/color tools](../surface-brushes.md) and
  [surface painting](../image-surface-paint.md).
- **Character and curve tools:** weight brushes, geometric mirroring and surface
  transfer; reviewed rig properties, drivers and IK; bounded Action lifecycle,
  stored F-curve inspection and interpolation sampling. These are scoped tools,
  not complete rigging, animation or character-quality acceptance. See
  [weights](../weight-brushes.md), [rig controls](../rig-drivers.md),
  [IK/deformation](../rig-ik-deformation.md) and
  [curves](../animation-curves.md).
- **Quaternion transforms:** optional raw WXYZ assignment in `transform.set` and
  transform previews, with independent six-channel expectations and guarded
  compensation. Targets must already use QUATERNION mode and meet the reviewed
  static, unlocked, local single-user Mesh profile. No normalization, sign
  canonicalization or mode conversion occurs. Quaternion requests are refused
  in batches. See the [exact contract](../object-rna-safety.md#quaternion-assignments).
- **Procedural, image and delivery foundations:** nested node workflows, bounded
  rigid-body evaluation, cooperative image/recovery/export jobs, and previewed
  approved-path GLB/FBX exchange for restricted assets. Format losses, file
  effects and retained partial work remain explicit. These foundations do not
  establish complete simulations, portable projects or production delivery.
  See [artist tools](../artist-tools.md),
  [rigid evaluation](../rigid-body-evaluation-jobs.md),
  [image jobs](../image-recovery-jobs.md) and
  [asset delivery](../asset-delivery.md).
- **Safety boundaries:** tighter ownership, consumer-scope, callback, checkpoint
  and request-lifecycle checks; explicit recovery facts when a failure may retain
  work. Candidate export/weight recovery changes require exact native validation
  before their tested behavior can be claimed. Checkpoints remain finite global
  undo history, not transactions or durable backups.

The [generated inventory](../../README.md#complete-tool-inventory--current-source)
lists the current tool surface. A registered tool name does not imply unrestricted
support for every operation, scene, Blender version or dependency graph.

## Important restrictions

- **Project saving is unavailable.** `project.save` returns `NOT_IMPLEMENTED` for
  Save and Save As before native/path access. This is a deliberate restriction
  relative to the older alpha. Save manually in Blender when intended; fixture
  serialization and in-memory recovery are not a supported save backend. See
  [project-save safety](../project-save-safety.md).
- Protected `viewport.capture` remains unsupported. Ordinary captures and
  structural comparisons do not qualify protected visual verification. See the
  [capture requirements](../protected-capture-design.md).
- Shader-interface REMOVE/conversion remains unsupported. Reviewed rename,
  reorder and default-value edits retain their bounded contract. See
  [shader interfaces](../shader-interface-lifecycle.md).
- Typed asset import remains quarantined on the known Blender **5.2.2** source
  build `d13f752e3b9c`; the refusal is containment, not a native import fix. See
  [asset import](../asset-import.md).
- The new private UV Edit Mode planner and storage probe are research. They are
  not wired into public admission, do not provide a public UV guard and do not
  establish editor preservation or recovery.
- Arbitrary Python remains disabled by default and requires four broad grants
  together. It is not a sandbox or a substitute for missing structured tools.
  Keep transport on literal `127.0.0.1`; never expose or tunnel the listener.

## Compatibility and validation status

Blender **4.2.0** remains the declared manifest minimum; standalone **Python
3.10+** runs the MCP server. The minimum is metadata, not qualification of every
Blender patch or operating system. The alpha classifier and protocol version
**1.0** remain unchanged.

Windows-specific compatibility work and Windows testing are **deferred**. No
Windows support verdict, complete native matrix, installed-package acceptance,
upgrade/rollback qualification or A–F workflow acceptance is claimed for this
candidate. Historical Linux development fixtures qualify only their exact
sources, native builds and bounded contracts. They cannot substitute for final
candidate evidence.

Candidate acceptance still requires the exact source, CI result, package hashes,
retained native reports and installation evidence to agree. This page contains
no future commit, test-count or publication claims. The full artist-workflow
target and remaining gates are tracked in the [1.0 plan](../plan-1.0.md).

## Packages and upgrade

Once an accepted prerelease is published, use its attached assets rather than
GitHub's automatic source archives:

| Asset | Purpose |
| --- | --- |
| `blender_codex_bridge-0.4.0.zip` | Blender add-on; install without extracting |
| `blender_codex_bridge-0.4.0-py3-none-any.whl` | Standalone MCP server |
| `blender-codex-bridge-plugin-0.4.0.zip` | Optional Codex plugin; uses the installed MCP command |
| `SHA256SUMS.txt` | SHA-256 checksums for the matching packages |

For an upgrade, finish active calls and stop the bridge, retain a normal backup,
replace the add-on and restart Blender to unload older modules. Upgrade the wheel
in the environment registered with Codex, update the optional plugin if used,
and start a new Codex session. Verify add-on/MCP versions and begin with read-only
inspection. The [installation guide](../installation.md) describes the connection
steps; use the matching candidate filenames above when candidate assets exist.

Do not mix 0.3.0 and 0.4.0 components or assume equal version strings identify an
unpublished source build. Protocol envelopes remain compatible; no automatic
`.blend` migration is introduced. Session references, previews, protected
baselines and checkpoint bookkeeping must be recreated after restart. Rollback
requires reinstalling the matching older add-on/server/plugin; it does not undo
scene edits or remove files already exported.
