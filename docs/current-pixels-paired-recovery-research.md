# Private current-pixel paired recovery prerequisite

This is a fixture-only reconstruction after the temporary execution environment
was restarted. The earlier small paired-recovery result and three successful 4K
phases remain historical reports. Their private source and direct RAM receipts
were lost. The prior 5.2 fresh reader refused before project open at the 8 GiB
preflight. None of those observations substitutes for qualification of this new
source. Root must retain new full-suite, exact-commit and native evidence.

The first reconstructed SMALL2X2 writers failed before helper creation or forward packing:
Image does not declare an `animation_data` RNA property on either pinned build.
That failed attempt is retained. The corrected projection records the explicit
`IMAGE_ANIMATION_DATA_RNA_ABSENT_V1` schema witness, including a bounded ordered
property-catalog digest. It refuses an unexpected declaration before helper or
forward writes. No missing attribute, exception or `getattr` fallback becomes an
animation-state guarantee; only the declared property's absence is measured.

The second reconstructed small run exposed a socket API error before any backup
or helper was created: native sockets use `bl_idname`, as the existing public
shader graph inspectors do, and do not expose `bl_socket_idname`. The corrected
socket projection retains the concrete registered class (for example
`NodeSocketVector`), not the broader `socket.type` category. It keeps identifiers,
native identities, defaults, flags and link endpoints without a type fallback.
The previous failed source/native results remain retained. The remaining
projection getter names were checked against public inspectors, the existing
native-save schema and bundled material UI declarations; this source audit does
not substitute for the next exact-source native run.

The opt-in `image_current_pixels_paired_recovery` and
`image_current_pixels_paired_recovery_large` cases use one implementation with
explicit SMALL2X2 and LARGE4K profiles. Both writer and fresh-reader phases run
interactively through the isolated runner and reviewed private display. They
attest the owned process before using the established owned exit; no ordinary
quit/recovery save is used. Three genuine deferred Blender timer observations
follow forward packing and three follow explicit recovery. The fixture never
manually invokes timers, runs a custom update loop or adopts observed state as
a replacement baseline.

## Exact declared data scope

One local FILE Float32 RGBA OPEN_EXR Image uses Non-Color and CHANNEL_PACKED.
It is already loaded and dirty, and its packed bytes initially contain older
pixels. Two real Material/Image Texture node graphs consume it through two
Mesh/Object material slots. A third Object/Mesh/Material/Image is unrelated
protected data. All three meshes are fixed three-vertex triangles with no UV
maps, shape keys, modifiers, constraints or animation. The original has two
native Material consumers before the owned helper is created.

Complete raw Float32 little-endian channel digests include signed zero, hidden
zero-alpha RGB and HDR data. In the 4K profile every blue component encodes a
unique `(y * width + x) / 2^24` index. The setup writes arrays by channel strides;
the independent oracle hashes separately packed scalar rows. The oracle is
never used as restoration input. The actual original buffer supplies canonical
EXR bytes through the existing codec.

The immutable pre-helper projection includes complete vertices, edges,
polygons and loop vertex indices; slots and material identities; declared
Object transforms and visibility; all input/output defaults and links in the
fixture's bounded native shader trees; Image roles, path, loaded/dirty state,
complete pixels, packed bytes and native direct consumers. Expected helper
effects are computed by recipe, with only its newly earned native identity
inserted after allocation. Existing source and protected data are never rebased.

This is a finite authored projection. It does not measure every shader setting,
UI/selection state, hidden caches, raw Main bytes, all native tags/notifiers or
arbitrary nested/animated/shared consumers. It provides no hostile Python or
filesystem sandbox guarantee and no visual material-appearance acceptance.

## Durability and explicit reverse transition

Before any helper creation or Image mutation after the baseline, the writer
publishes three fixed create-only files: `previous-packed.bin`,
`current-pixels.exr` and `manifest.json`. Each file and its parent directory is
fsynced. Closed files are independently reopened and completely hashed; inode,
device, length and mtime are checked during readback. A failed or incomplete
publication retains files and stops before Image changes. This is verified
filesystem durability, not a power-loss or hardware guarantee.

The distinct helper uses the existing schema-1 CURRENT_PIXELS metadata and a
real native `image_portability.OWNER_KEY` Image reference. A separate private
record links its UUID to the immutable manifest hash. This fixture creates the
helper directly to study the native primitive; it does not exercise the public
snapshot job or grant any public lifecycle permission.

The original receives complete verified current packed bytes before its loaded
buffer is discarded. A native decode from those packed bytes must preserve all
edited pixels and the declared graph. A separately labelled owned fixture save
records that portable edited original and native helper graph. It is not a
qualified public Save/delivery path and does not change H01 limits.

Explicit recovery independently reopens old packed bytes and canonical current
EXR. The existing bounded canonical decoder supplies current pixels, never a
retained source array, helper buffer or encoder recipe. Recovery restores old
packed bytes and then the edited, dirty buffer on the same existing Image.
Every declared target and protected field must match the expected state.

The fresh reader verifies the saved-file hash before opening, finds the helper,
resolves the original through its actual native OWNER relationship and verifies
the first original pixel read before any restore. It does not select the original
by name or deserialize a pointer/UID into a new process. Cross-process comparison
omits historical native tokens while retaining the complete declared graph.
The native current graph and retained saved-file provenance are not a universal
historical-identity proof against file/script rewriting.

## Resource and evidence gates

The large profile is exactly 4096 × 4096. Each old/current payload is at most
257 MiB; the private project is at most 530 MiB; the immutable manifest is at most
64 KiB and each report at most 2 MiB. Complete byte comparisons and project
hashing stream in 1 MiB blocks. The large writer and reader require point-in-time
measured cgroup-aware memory headroom of at least 8 GiB and filesystem free space
of at least 2 GiB before large allocations. The measured facts are persisted
before either assertion, including on refusal. These checks are neither resource
reservations nor constrained-memory proof.

Each native phase keeps a 300-second deadline. Root's outer phased wrapper may
use 1200 seconds; the two new runner aliases independently cap each native
process at 300. Reports retain actual blocking intervals, process-instance/build
identity, whole-process peak RSS and complete graph/channel witnesses. Compact
markers bind the complete receipt by length and hash. Root may evict closed-file
cache pages or run builds separately to provide headroom; it must not lower the
limits or erase failed observations.

There is no new public tool, permission, Runtime, job service or schema. Public
current-pixel packing/recovery, interruption and earned partial recovery,
constrained-memory behavior, broader color/alpha roles, protected artist scopes,
4K production Save, installed packages and complete A04/I02 remain open. The
helper and external backups are retained owned effects, not exact pre-helper
rollback. No automatic inverse, Image recreation or native-undo backup is claimed.
Windows compatibility/testing remains deferred by the user.
