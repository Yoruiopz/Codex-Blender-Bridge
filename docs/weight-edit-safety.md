# Retained direct weight edits

The source routes `weights.assign` and `weights.normalize` through one original
factory, immutable Float32 plan and field-only recovery boundary. Their public
arguments, `weights` toolset and Blender-authoritative `EDIT_MESH` permission are
unchanged. Other weight tools are not changed or qualified by this increment.

The bounded ordinary stock-Blender reader/call window is implemented in source
for the recorded Linux 4.5.14 (`62c1db4208e8`) and 5.2.2 (`d13f752e3b9c`) builds.
Selected native checks passed on both builds at the sources recorded below;
broader native qualification remains incomplete. The early Mesh-runtime-metadata
refusals remain historical evidence, rather than current success. Unknown builds,
origins and unsupported profiles refuse with `NOT_IMPLEMENTED`; portable models
alone do not qualify native behavior. The old two handlers' context-free
compensation path is no longer used. No installed, full character-workflow,
Windows or 1.0 acceptance follows. All 29 implementation items and 14 release
gates remain open; Windows work remains deferred.

## Implemented ordinary source profile

The initial admission proposal is one explicitly named, local editable
non-override Object and single-user Mesh in Object Mode, with no live Edit
buffer. Groups and populated deform storage already exist; only explicit vertex memberships change. Target
groups are unlocked; every other group and vertex is preserved. Linked/shared,
unknown consumers/storage, parenting, modifiers, constraints, animation,
instancing, shape keys and unsupported material/UV/color/custom-data profiles
are refused rather than stripped. USER properties on the target Object/Mesh
must be empty. Reviewed bundled Object runtime descriptors are allowed only
when native noncreating presence checks find no stored value. The exact Mesh
`cycles` POINTER must refer to the empty bundled `CyclesMeshSettings` schema,
with only the canonical inherited `rna_type` and `name` descriptors. Both pinned
builds require `is_property_set(..., ghost=False)` to return exact `False` before
admission. Existing 4.5 USER or 5.2 SYSTEM storage is refused; neither the runtime
pointer getter nor a raw-storage fallback runs. Descriptor/group/base pointers
and metadata enter the retained comparison projection. Unknown runtime
descriptors refuse before payload getters. This is not a SYSTEM-property or
complete hidden-storage witness.

The source screens at most 256 current-Main IDs for canonical native identity
and absent animation data, requires no Actions/libraries/Texts and no
frame/depsgraph Python handlers. The target belongs to exactly the current
Scene and one to eight direct local unshared leaf Collections. A bounded native
user map must show only the target consuming its Mesh and the expected
Scene/Collection consumers of its Object. It snapshots raw target transforms,
geometry/corner topology, element selection/hide flags, group inventory,
semantic memberships and reviewed attribute metadata, plus Main ID identities,
Scene/frame/view-layer/filepath and authenticated checkpoint markers. It does
not serialize every unrelated ID or read selected/active/context-mode getters.

The caps are 512 vertices, 1,024 edges, 512 polygons, 2,048 corners,
32 groups, 256 changed membership fields, 65,536 retained scalar values and
2 MiB serialized evidence. The existing 1–1,000 explicit-index argument bound
remains; actual indices must fit the admitted mesh. Joint comparison work is
limited to 8,388,608 values, including a maximum read and reserved compensation.
Individual caps do not guarantee their combination fits. Over-budget input
refuses; no subset is silently sampled.

These are standalone calls. Their existing automatic checkpoints remain enabled
and the new exclusive bridge lease rejects structured reentry. Guarded batch
children are not reviewed and refuse before child providers/checkpoints. No
protected-scope resolver is added: artist-plan protection continues to refuse
these writes. A bridge lease does not exclude arbitrary native/Python callbacks.

## Implemented portable boundary

Before entry providers, retain the exact bounded plain request, registered
spec/services and complete admitted original. Build one frozen plan; a later
handler must consume the same original factory binding. Recapture, substituted
plans/readers/services, changed parameters and replay refuse.

Assignment distinguishes an absent membership from present positive/negative
zero. Normalization retains existing selected-group arithmetic and all
untouched-group weights. Expected values are rounded independently to exact
little-endian Float32 bytes before native readback; exact no-ops issue no setter.
All memberships, group name/index/pointer/lock inventory and the reader's full
supported preservation projection must match the current expected prefix.

Every field runs live permission/caller/stop checks, full prefix comparison and
fresh target/group resolution before its leaf call. The reader must verify
Object/Mesh native pointer **and session UID**, exact native schema, group owner,
pointer/name/index/lock facts and in-range vertices. No Python `id()` fallback
or retained native weight-array wrapper is allowed. Complete CAS precedes the
genuine native method leaf; no provider or broad read occurs while it is held.
References are cleared in `finally` before post-readback or compensation.

Each native attempt is counted before entry, including calls that throw. The
complete result must equal precomputed old or next state. Only a verified next
state advances the expected prefix and creates an owned restoration entry.
Unknown effects, unreadable state, foreign changes or authority loss are sticky:
no later field, restoration or cleanup/update writes. Ordinary failure may
restore only verified attempted fields, in reverse order, while authority and
the complete prefix still match. Recovery never rewrites unattempted fields.
`rollback_verified=true` requires full measured equality to the original
supported authored state, excluding authenticated checkpoint-marker progression.

The guard adds no Mesh, Object or ViewLayer update calls. Native VertexGroup
methods themselves tag geometry and queue notifiers; zero explicit-update
counters do not mean native allocation/runtime purity or passive checkpoints.

## Ordinary native window and remaining prerequisites

Exact-source review shows the membership C bodies directly preserve group
definitions while resizing/freeing per-vertex weight arrays; removal may reorder
their entries. No membership wrapper survives a setter. Fresh pointer facts are
retained; a non-ID group's name/index/pointer equality is not a universal
remove/recreate or allocator-reuse certificate. The useful ordinary profile
must close genuine add/remove calls after trusted providers and builtin argument
preparation, with no yield/reentry or group-definition mutation in that interval.
Unknown provider/method/hook origins must refuse. Arbitrary in-process mutation,
finalizer behavior and stronger historical identity remain unverified.

Exact-source review of both recorded commits shows that the Mesh accessor may
copy on write, and absent deform storage would allocate a layer; the initial
populated-storage profile excludes the absent-layer case but still permits
declared copy-on-write allocation. Membership arrays can resize, move and free.
Geometry tagging changes recalc/graph state; the `ID_RECALC_EDITORS` immediate
editor-callback branch is separate from these GEOMETRY calls. Notifiers allocate
and enter the event queue. These paths do not explicitly run dependency-graph
evaluation or immediate notifier listeners. Python/RNA conversion and report
handling can allocate; exact prebuilt builtin tuple/int/Float32/enum arguments
avoid caller-defined numeric/sequence conversion in the leaf. This is finite
source evidence, not proof against arbitrary finalizers or in-process mutation.

Native origin screening requires the main thread, canonical active
`BridgeRuntime`/`MainThreadExecutor` services, the original default preference
provider function/code/globals, and either direct hooks or the actual queued
request's known cancel/final-hook implementations. The exclusive bridge lease
remains authoritative. Unknown hooks/providers and active scene jobs refuse.
The supported ordinary boundary is Runtime/Executor dispatch with trusted
in-process code and no yield or group-definition mutation across the fresh
leaf. Arbitrary Python reusing native services/direct registry contexts or
mutating classes, modules, memory or callbacks is outside this qualification;
remote MCP arguments cannot supply these object identities. No stack inspection
or caller-set origin flag grants admission.

No custom Blender build, private memory offsets, raw fallback
or weakened pointer witness is introduced. The handler-local
[brush boundary](weight-brushes.md) and its ViewLayer update are not passive
pre-provider evidence for these tools.

Automatic global undo may write markers or serialize/evaluate outside the target
before/after the handler. Require existing usable undo settings without changing
preferences. Target membership CAS does not cover dirty unrelated animation,
drivers/embedded animation, pending hidden-selected Base synchronization or
unbounded checkpoint callbacks. Source-qualified static/global refusal and
native context evidence remain separate requirements. An empty Actions
collection alone proves none of those. Never normalize input using frame
evaluation, a ViewLayer update, save, held Timeline/provider reproduction or
fixture-only checkpoint replacement. No full hidden USER/SYSTEM/native purity
or full selection-preservation certificate is claimed.

## Recovery facts and verification

Responses and operation history retain the existing bounded `weight_mutation`
receipt for these two exact methods: attempted/verified/restored counts,
before/expected/observed digests and known/partial/rollback/refusal facts.
Unknown state has no observed digest. The two direct methods retain at most
256 membership/restoration counts and zero explicit-update counts; existing
brush limits, redaction and generic history behavior stay unchanged. A receipt
grants no restore authority.
Checkpoints and in-memory snapshots are not durable backups or transactions.

Focused models exercise registered factories, request/provider drift, exact
Float32/absence/zero behavior, whole-membership CAS, throw-before/after-write,
foreign edits, revocation, field-only recovery, exclusive reentry, batch refusal
and typed history. They do not qualify native group identity/storage or undo.
The opt-in isolated case `weight_edit_guard` uses the genuine registered Runtime,
Executor, permission source and automatic checkpoints. Earlier source
`415e0c1140f7ae11608166ea4762c23118235056` passed assignment, normalization and
permission denial on official Linux 4.5.14 and 5.2.2. That evidence does not
qualify later fixture changes or native recovery.

The extended fixture adds three adverse cases: an injected failure after the
first applied setter with authority retained; actual edit-permission revocation
at that boundary; and an external write to another group's membership. It
independently compares complete Float32 membership bits, group names/indices and
pointers, original Object/Mesh UIDs/pointers, direct native consumers, transforms
and authored mesh geometry. Expected outcomes are assertions, never edits to a
production receipt: measured compensation in the first case, retained first-write
state without an inverse in the second, and preservation of the external write
with inverse refusal in the third. Failed operation history must retain the same
bounded recovery facts. A permission-revoked first write has one verified
membership and zero restoration attempts: `_member` releases its leaf, runs the
provider-free `_read`/pure `_final`, verifies the complete first prefix, and only
then reaches the next `_live` permission-provider call. The foreign-membership
case instead fails that complete prefix comparison before incrementing verified
memberships. These expectations follow the production control flow; a changed
native receipt must fail the fixture rather than be rewritten.

The expanded projection initially failed on both builds at fixture commit
`4f5cbeb5237d748f253bc8b6e043aedf2d8450b6`. The 4.5 permission assertion expected
the wrong verified count. The 5.2 ordinary-call comparison failed before its
snapshots were retained, so the changed header/consumer field remains unknown;
that run is not cold-context preservation evidence.

The current fixture performs an explicit genuine `checkpoint.create` as declared
disposable-scene preparation before capturing any original weight-call state or
intent. It retains preparation-before/after target, Scene headers/UIDs, native
consumer/WindowManager role observations, field-path differences and the native
checkpoint receipt separately. This preparation may stamp Scene markers, tag the
project modified, push/encode the native undo stack and create native override
operations. Those source-described effects are not a complete side-effect
inventory, and the fixture does not promise preparation preserves hidden state.
Cold-context expanded preservation remains unqualified. After preparation, every
weight-call comparison still requires exact complete UID/header/consumer and
Float32 preservation; no post-tool snapshot becomes its baseline and no field is
removed to accept drift. Ordinary and adverse attempt rows, full projections and
bounded diagnostic differences are retained before assertions, including failed
rows. The bounded differences do not replace the complete retained projections.

Blender's native `bpy_func` callable is a custom C `tp_call`; Python C-return
profiling cannot establish that it ran. The fixture observes the exact unchanged
`_NativeLeaf.__call__` wrapper and tracks exceptional exits. After that wrapper's
`finally` releases its native method, the observer disables itself before the
explicit external event. A separate complete stored-state projection must prove
the first predicted membership was actually applied. Wrapper entry/return
counts are recorded distinctly from unobserved C-return events. No native
method, reader, checkpoint or permission provider is replaced. Profiling/trace
hooks and local permission fields are restored on error.

These injected external events are not passive native-read or provider-purity
evidence. Native method dependency tags, copy-on-write and notifiers, hidden
caches and full Main state are outside this fixture's projection. Native global
undo, mixed manual undo, history eviction, real queued/TCP cancellation and
disconnect, memory pressure and character deformation remain unqualified. A
retained snapshot or undo history is not a durable backup.

At `f65e3e6653a38f13d4fa391bbeb94ab94f0268a6`, root's isolated replay passed all
six cases on both official builds after the explicit setup checkpoint. The
applied-write failure measured one verified membership, one restored membership
and verified rollback. Permission loss retained one verified membership with no
inverse attempt. Foreign interleaving retained zero verified memberships, made
no inverse attempt and preserved the external write. The original cold 5.2
expanded header/consumer mismatch remains unidentified and unqualified; the
successful prepared-context replay does not explain it. This source-specific
evidence does not qualify later integrations or add cancellation, disconnect,
native undo, durable recovery or constrained-memory proof. Root owns exact
integrated full-suite and native qualification; an unsupported native gate must
fail the fixture rather than replace the production reader.
Existing broader artist/character fixtures remain mandatory and must not be
rewritten to hide profile refusals. Full F01/F03/C02 and stable release acceptance
remain incomplete.
